## 已修复及实际根因

1. **36 氪原文读取。** 普通 HTTP 返回火山引擎检测页，正常浏览器能读取已验证的文章，不需要先登录。原适配器走错读取路径，并在页面正文渲染完成前过早解析；不是三筛判断规则本身出错。现改用本轮已有浏览器会话，等待标题和正文就绪，发布时间取文章可见时间。实际重新读取：快讯 `4052573767111560` 正文 251 字符；文章 `4051860578702216` 正文 6678 字符。科技栏目原批次恢复后完成，未整批重新采集。
2. **已知启动与 BrowserSkill 兼容。** 正式入口负责恢复配置中的 daemon，避免 CLI 隐式后台拉起引发 Windows Job Object 错误；CLI、daemon、扩展为 0.4.1，协议 1.8。统一适配器保留 strict 和同次 sync 的凭据。浏览器主标签留在原生扩展页或网络错误页时，后续标签操作会失败；扩展操作后必须恢复正常网页，UI Automation 选择标签后须等待并确认选中状态。
3. **宿主策略错误。** 本地历史已记录“调试启动、导航、观察组合命令被拒绝，分开提交可执行”。本轮沿用同一 PowerShell 分开执行成功，没有改解释器或策略设置绕过拒绝。宿主具体匹配规则没有证据，未声称所有策略限制都已消失。
4. **替换平台操作。** 采用固定校验和的官方 Wechatsync 2.0.9 扩展；官方发布包实际包含头条驱动，而所查公开源码树没有该实现。保留上游账号检查、上传和提交，在接入层补齐摘要、封面、图片样式、指定任务标签、原位更新和回读。旧 `toutiao_publisher.py`、`wechat_resume.py`、公众号编辑器点击/粘贴及独立 profile 实现已删除；Playwright 依赖和旧 Easel 许可证目录也已移除。工作台仍保留业务任务、审稿、操作记录和独立内容核对。
5. **公众号兼容差异。** 上游会重建图片标签，导致样式丢失；微信保存后也会调整图片地址和封面裁切。现保留图片样式，对改变的图片地址核对实际图片内容。原稿更新必须同时使用 `sub=update` 与 `AppMsgId`。第一次补接更新仅传 ID，误建了 `100000089`；该错误已保留记录，原稿 `100000084` 经独立核对后完成原位更新，误建稿随后删除并从完整列表确认消失。恢复流程也增加原稿 ID 绑定检查，不接受其他 ID 替代原稿。
6. **头条兼容差异。** 扩展上下文上传图片未得到可解析响应，改为复用已登录页面的正常请求环境；提交默认广告值 `3` 被本账号以“无头条广告权限”拒绝。现按当前官方页面使用不投放广告值 `2`。单图封面值为 `2`，此前误用 `1` 实际表示无封面；已沿原草稿 ID 修正。官方页面代码明确草稿 `save=0`、发表 `save=1`，本接入只提交草稿。
7. **扩展连接闲置断开。** 上游 WebSocket 无消息时，Chrome MV3 会挂起扩展线程。加入本地连接心跳和断线唤醒；该心跳只访问本机，不向内容平台发送请求，也不等于登录续期。依据见 [Chrome 官方文档](https://developer.chrome.com/docs/extensions/how-to/web-platform/websockets)。
