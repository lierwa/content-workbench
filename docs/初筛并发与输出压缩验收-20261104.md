# 初筛并发与输出压缩验收 · 2026-11-04

本轮只优化初筛执行与重复输出。真实模型对照显示，同一批 64 个事件的初筛耗时从 284.102 秒降至 113.677 秒（减少 60.0%），未缓存输入减少 15.0%，输出减少 39.8%。这是初筛局部对照，不是集合稿交付或整条生产流程验收。

## 实现

- 分段分配给两路执行；每路内部串行复用自己的模型会话，两路不会同时写同一会话。单个工作台进程内跨栏目合计最多 2 次初筛模型调用。
- 未晋级项只输出决定与一句理由；晋级依据最多两条短引文，标签和维度引用引文编号。程序校验后还原已有存储格式，后续阶段与页面继续读取原结构。
- 每段完成即保存，汇总恢复输入顺序。排队时可取消，调用失败保留其他成功分段。新契约单独进入初筛阶段指纹。
- 回执增加并发槽等待时间，原 elapsed_seconds 仍记录实际调用耗时。

## 真实模型对照

使用正式历史批次 `hotspots-20261104-201716-03597634` 的前 4 个原始分段，共 64 个事件。三组的输入哈希、栏目规则、冻结时间和 AI 设置相同，均使用 Terra / low；每组重新执行，未指定入选名单。仅在临时目录运行初筛，不运行采集、二筛、取材或写稿。

中间版本虽然较快，但未缓存输入增加 33.6%，因此没有采用。最终实现兼顾本次观测到的耗时和用量。三组真实实验合计 12 次调用，输入 164,199（缓存 80,640、未缓存 83,559），输出 29,672，总计 193,871 token；未换算金额。

最终实现完整处理 64 个事件，全部引文和结构校验通过，没有纠错追加调用。旧版晋级 16 个，新版晋级 20 个；5 个事件的决定发生变化。入选变化说明模型判断并非固定，不代表已经证明整个候选池的筛选质量提升。当前仅能排除漏处理、重复处理、引用失效和通过少处理事件制造提速；不将本次单轮结果承诺为所有批次的固定降幅。

## 临时验证与生效

- 两个栏目并行的临时检查：初筛实际并发峰值 2，同一会话同时使用次数不超过 1，结果顺序正确。
- 无效、重复、负数和布尔型引文编号均拒绝；已有引文结构仍可读取。
- 排队取消不触发模型调用；成功分段重用不新增调用。
- 模拟一段失败后，成功段检查点保留；续跑只调用失败段一次。
- Python 导入/语法及差异空白检查通过。没有新增仓库测试文件、框架或测试素材。
- 确认正式采集、筛选和制作均空闲后重启工作台加载改动；保留原批次、稿件、栏目与账号配置，没有清库或重新运行正式生产。

时间核实要求、成稿来源写法、二筛取材配额及不足后补筛尚未在本轮修改；科技简报未交付的问题仍需后续处理。
