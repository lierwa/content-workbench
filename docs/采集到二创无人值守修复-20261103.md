# 采集到二创：中断、成本与修复验收

11 月 3 日实跑，15 个渠道用 6 秒采到 268 条线索。从开始采集到最后一篇本地稿完成共 40 分 45 秒。首次中断时两个栏目都停了，无人接手交付 0 篇。最后的两篇本地稿里，科技简报换了较小的输入范围，热点稿靠手动返修和续跑。原批次无人值守验收失败。终点是审稿通过的本地稿，位于 WechatSync 同步之前。

## 把 token 花在选准题、核实事实和写稿上

本轮有 66 次 AI 调用，64 次返回用量，合计至少 **1,344,978 token**。其中事件归组 12.64 万，一筛 36.56 万，二筛至少 22.38 万，三筛正文核实 4.94 万，三筛后选题 2.68 万，改稿加复审至少 35.45 万。这些数包含失败和补跑。按各调用目录的回执统计，不能只看筛选批次或拿最终两篇当自动交付数。

- **一筛**保留热点的八项匹配：观众想纠正你、看翻车、打假、站队、蹲后续、当军师、代入自己、证明自己。允许空匹配，保留命中依据，不按标签数量晋级。科技用自己的栏目规则。先压掉重复的栏目说明、接近全文的摘要和淘汰项重复长理由。规则见[八项读者动机](筛选规则.md)。
- **归组和二筛**先复用已确定的重复记录、事件与判断。二筛用一份精简候选表比较，以入选原因和取材目标为输出。保留三筛读原文，以及三筛后独立判断二创价值的 AI 调用。入选不足可少选或零选，不拿二筛排名直接进二创。
- **出稿与质量**去掉后台改稿提示词里询问用户是否模仿作者之类的无关内容，返修只传解决问题需要的材料。科技样稿把吉利新车和百度仿真测试并列，验收时看两条是否服务于同一读者问题，主题不成立就分开选或少选。热点稿看标题提出的问题是否被正文用具体事实回答。保留独立事实复审。
