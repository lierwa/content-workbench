# 图文草稿开源实现索引

## 2026-11-03 实际采用方案

采用官方 Wechatsync 2.0.9 发布包中的公众号、头条适配器，工作台补齐封面、摘要、原位更新、图片样式及独立回读。源码固定提交的公开树缺少头条实现，但官方发布包包含该实现；这是本次选型更新的明确依据。原调查发现的封面、摘要和样式缺口仍然成立，不能将官方包当作无需适配的完整成品。

已删除旧公众号/头条编辑器操作实现与独立 Playwright profile 路径。安装、固定版本、上游来源和具体修改见 [Wechatsync 接入](../integrations/wechatsync/README.md)，实际运行结果见本轮结束报告。头条现行页面源码已明确 `PUBLISH=1`、`DRAFT=0`；无广告值为 `2`，单图封面值为 `2`。公众号原稿更新需同时指定 `sub=update` 和 `AppMsgId`。

以下保留 2026-10-30 只读核查的历史结论，代码位置和下一步建议均对应当时版本，不再作为当前运行入口。

## 微信公众号：优先复用现有 Easel 适配

- [Easel `weixin_mp_stats.py`](https://github.com/ZJU-REAL/Easel/blob/5a597e5f3ef5b01098b53f36caf719dd9a32b7bf/skills/shared/scripts/weixin_mp_stats.py#L601)，Apache-2.0。`_editor_ctx` 从编辑器页获取 `ticket` / `user_name`；`cmd_publish` 中 `_upload_material` 将封面和正文图片分别上传到 `filetransfer`，用返回的 CDN 地址替换正文图片；`operate_appmsg` 的 `content0` 接收 HTML，`thumb_media_id0` 和 `cdn_*_url0` 携带封面，成功时取回 `appMsgId`。原入口自行启动和关闭 Playwright profile，不能原样当成复用现有 BSK 浏览器会话的入口；其正文图上传失败会保留原地址，应由调用方显式阻断。
- 本项目 [platforms.py](../single_pass/platforms.py) 的 `_wechat_save` 已按上述方案适配独立 profile；`vendor/easel/` 当前只含许可证，并非完整上游源码。复用现有登录浏览器需把现有上传、封面、表单和响应处理与会话传输适配起来，保留身份核验、图片映射与远端回读；不应再另起 profile 或重写整套编辑器。
- [Wechatsync `WeixinAdapter`](https://github.com/wechatsync/Wechatsync/blob/42f61e39e214b8d5377d09d788a716defc4abdc0/packages/core/src/adapters/platforms/weixin.ts#L141)，仓库 GPL-3.0。使用扩展会话和 token，经 `filetransfer` 上传正文图，再把 HTML 写入 `operate_appmsg`。所查版本会剥离非微信域名链接、应用默认 CSS，并把封面及摘要留空，不符合本项目完整稿件的直接复用条件；其扩展请求、动态 header 规则和当前 BSK 会话能力也并非相同接口。
- [Wenyan Core `publishToWechatDraft`](https://github.com/caol64/wenyan-core/blob/b1c9edc7c13b8a5e110d29266aa849dfbc4dc6ef/src/node/publish.ts#L113)，Apache-2.0。接收 HTML，用 JSDOM 定位正文图并上传、另传封面，再调用草稿 API；[客户端](https://github.com/caol64/wenyan-core/blob/b1c9edc7c13b8a5e110d29266aa849dfbc4dc6ef/src/wechat.ts#L88) 使用 `api.weixin.qq.com`、AppID/AppSecret 和 access token，项目文档要求 IP 白名单，不直接使用现有网页登录状态。

## 今日头条：可参考公开旧驱动，不能直接当作已验证草稿方案

- [Wechatsync 旧版 `ToutiaoAdapter`](https://github.com/wechatsync/Wechatsync/blob/9d9b9283a6a7f177881c884e901632880a0a0da6/packages/%40wechatsync/drivers/src/toutiao.js#L32) 的 `editPost` 将 HTML 放在 `content`，提交至 `/mp/agw/article/publish`；封面以 `pgc_feed_covers` 传 URL、URI 和尺寸。`uploadFile` 使用 multipart 的 `upfile` 调用 `upload_picture`，`editImg` 给图片写 `web_uri`；`preEditPost` 会移除外链。源码中的 `save: 0` 是否代表保存草稿，以及旧接口当前是否有效，均未证实，不得据此直接提交。旧仓根许可证为 GPL-3.0，但 `packages/@wechatsync/drivers/package.json` 标注 MIT，复用源码前需澄清声明的适用范围。
- 当前 Wechatsync v2 的 [公开平台索引](https://github.com/wechatsync/Wechatsync/blob/42f61e39e214b8d5377d09d788a716defc4abdc0/packages/core/src/adapters/platforms/index.ts) 写明私有驱动动态加载，公开树中没有头条 adapter；[头条 content script](https://github.com/wechatsync/Wechatsync/blob/42f61e39e214b8d5377d09d788a716defc4abdc0/packages/extension/src/content/toutiao.ts) 是请求桥，不包含完整草稿填充实现。上游有[图片上传失败报告](https://github.com/wechatsync/Wechatsync/issues/224)，不能把产品支持列表当成本账号成功证据。
- [OmniPost `TouTiaoArticle`](https://github.com/rehatRobot/omnipost/blob/23f30666e0fbbfc6373ed97394daea82acb0a0e5/uploader/toutiao_uploader/main.py#L413)，MIT。`fill_body` 通过 `clipboard.writeText`、键盘或 `innerText` 写纯文本；`handle_cover` 使用文件选择器或文件输入设置封面；`upload` 启动新 Playwright 浏览器并导入 storage state，最后调用发布，未见本文路径的显式保存草稿实现。它可参考封面交互，但不能原样满足现有会话、富文本、正文图和草稿要求。

接下来应沿现有头条适配核查可回读的真实草稿、正文图片及封面映射，遇到提交结果未知先回读，不按旧驱动猜测参数重试。两平台的实际格式和回读结论均以目标账号证据为准。
