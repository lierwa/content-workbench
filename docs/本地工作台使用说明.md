# 热点集合本地工作台使用说明

本轮在 Windows、Python 3.12.10 环境验证了本地服务和五源采集，无需安装第三方 Python 包。命令声明支持 Python 3.9+，其他版本尚未实测，建议新环境先用 Python 3.12。未来运行在另一台电脑，其操作系统及部署条件尚未验证。用户计划于2026-10-29自行创建两个平台账号，现在尚不能发布。

## 启动与采集

在项目目录打开终端，启动工作台：

```powershell
python -m workbench serve --host 127.0.0.1 --port 8765
```

保持终端运行，在同一台电脑浏览器打开 `http://127.0.0.1:8765/`。关闭该终端或按 Ctrl+C 可停止自己启动的服务；如果端口被占用，可换一个空闲端口，同时使用对应地址。仅监听本机回环地址，不应直接暴露到公网。

网页点击“手动采集”会生成新批次，也可在项目目录单次运行：

```powershell
python -m workbench collect
```

默认数据文件为 `data/workbench.sqlite3`；它不随仓库提交，新克隆须先执行采集或点击“手动采集”，才能取得该机器的新候选。要在隔离数据中试用，可在子命令后加 `--db 路径`。真实运行时各源单独报告成功、条数或失败；一个来源失败不会用其他来源的成功掩盖。榜单可能变化，不能保证每次都能取到同样条数或长期可用。

五个当前来源为头条、百度、B站官方数据，以及微博、知乎第三方聚合。采集取得的是各榜单返回的基本条目，不额外取事件正文；保留标题、链接、来源、采样时间和可获得的事件时间、封面 URL。事件时间无数据时显示未知，不能将采样或报道时间当事件时间。第三方来源和站方显示的榜单时间应单独辨认；其指标是来源展示值，不可跨平台直接比较，也不应称为阅读数。封面只保存 URL，浏览器展示时会向该 URL 请求图片，不等于有转载授权。

同一来源、同一身份的候选在后续采集时复用并保留选择状态；跨来源相同标题仅作为可能重复提示，需人工判断，不能称为语义去重。榜单标题是线索，不能当成已核实的事件详情。

## 选择、详情与稿件确认

1. 在网页的“待选”中浏览，可按来源或关键词筛选、翻页；勾选后点“采用”“待定”或“排除”，决定会保存，可在对应状态中查看。
2. 打开“已选”素材。填入具体文章链接获取原文；若站点受限或链接是搜索结果而非具体文章，先找到可核验来源，或手动输入已核实的材料并附来源 URL。手工录入会标明来源方式；遇登录、验证码或风控时停止，不绕过。
3. 依据已核对的事实及必要后续，整理自己的简短标题、正文和讨论角度，保存并预览；保留来源，不把复制原文当二创。工作台目前不会自动生成稿件或调用 AI 服务。
4. 用户在网页独立点击“确认当前稿件”。确认只对应当前稿件版本，不代表发布；改稿或更新素材后需重新确认。平台账号和权限具备且在已授权范围内，才能另行操作发布并回读核实。

也可由助手协作：用户先在网页选好候选，再在**能访问该项目的 Codex 会话**说“处理已选”；助手读取已选项，补详情与核验，经工作台 API 回填短稿，用户回到网页独立确认。这是人工发起的协作，勾选不会自动启动助手或后台模型；无需新增付费 AI API。未来电脑需要既能运行工作台，也有能够访问同一项目与数据的助手环境。API 细节见[工作台接口](workbench-api.md)。
