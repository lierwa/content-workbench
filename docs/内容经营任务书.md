## 一 项目目标与最终交付

本项目要验证：围绕一群明确的读者，能否持续找到吸引他们的素材，以较少人工时间完成筛选、整理、发布，并用实际表现判断是否值得继续经营。第一轮服务于微信公众号和今日头条，长期逐步扩展为账号矩阵。

项目的交付主体是可以反复执行的流程、真实内容成果和效果记录。软件只承担其中有明确收益的辅助工作。文档完成、工具安装完成、页面可以打开，都不能代替内容流程完成。

首轮结束时，应交付以下成果。它们可以先以本地文件和清单存在，具体工具由实跑需要决定。

首个最小链路先验收一个平台；另一平台、按规则生成每日候选和自动发布分别保留完成状态。只有这些目标各自有实际结果后，才能将首轮目标整体标为完成。

| 成果 | 用户实际拿到什么 | 解决的问题 |
| --- | --- | --- |
| 首个账号定位及依据 | 目标人群、内容范围、真实对标作品、选择理由和待验证假设 | 为什么先做这个方向 |
| 可用的素材来源与收集方法 | 来源清单、真实采集样本、获取办法、缺失项和替代来源 | 明天继续去哪里找内容 |
| 可筛选的候选内容 | 带原始链接、素材预览或定位方式、推荐理由的候选清单 | 今天有哪些内容值得看 |
| 人选后的发布内容 | 选题、标题、正文或解说、配图或视频、来源及两个平台的必要适配 | 用户选中后怎样变成可发布内容 |
| 发布操作方法与实际结果 | 每个平台的操作方式、实际草稿或作品状态、成功证据及失败记录 | 内容是否真的发出去，自动化做到哪一步 |
| 复盘及下一轮调整 | 选用情况、人工耗时、阅读互动、可见收益和规则调整 | 继续、缩小、换方向，还是补一个工具 |

长期经营目标包括积累受众和验证收益。首轮流程验证不设虚构的阅读量或收入承诺，收益结论以账号实际数据为准。

## 二 已确定的要求与待验证的选择

### 已确定的要求

1. 平台先覆盖微信公众号和今日头条。账号矩阵是后续方向，第一轮先围绕一个定位验证。
2. 内容吸引力是核心：可以来自共鸣、争议、好奇、反差、幽默、猎奇、爽感，也可以来自读者想补充、纠正或表达不同观点。是否有知识含量不是统一门槛。
3. 主要工作是收集、筛选和组织已有素材，用户参与选题和最终内容判断。AI 可以辅助，但不依赖持续生成长文或昂贵模型调用。
4. 各账号有各自的人群和内容标准；素材收集、筛选、人工挑选、内容准备、发布和复盘尽量共用方法。
5. 以最低可行成本运行。现有条件为本地电脑和 Codex 订阅，不安装 Docker，不新增付费 API 依赖。
6. 自动发布属于目标流程。先人工验证的部分要保留记录，后续逐步替换重复操作，不能在人工发布之后宣称自动化已经完成。
7. World Monitor 只是可选来源工具。只有提供实际可用素材时才保留在链路中，项目推进不依赖它。
8. 优先完成流程成果。是否建 Web 系统、数据库、调度服务或专用界面，均由实际问题决定。

目标日常流程为：短频快地自动采集热点基本信息，在本地网页交用户选择，选中后采集详情和必要后续，轻量二创、独立人工确认，再发布并依据数据复盘。基本采集不研究正文。初期允许人工发起和协助；各环节自动化程度要按实测记录。发布频次和单位时间成本由实跑测量。

### 待验证的选择

| 事项 | 当前处理方式 |

| 首个账号定位 | 用户已选择“热点集合”，见[首个账号卡](../accounts/首个账号.md)；受众和实际效果待验证 |
| 第二类账号 | 尚未确定，不提前指定为搞笑、猎奇或其他方向 |
| 情绪选择 | 根据人群和具体素材判断；焦虑只是可能的切入点之一 |

| 账号是否现成、权限是否具备 | 微信和头条均无账号；用户计划2026-10-29自行创建，注册后的发布权限、可用格式和登录流程尚未验证 |

本文的样本量、轮次和时间预算均为首轮执行默认值，便于控制投入；它们不是经过验证的行业标准。

## 三 首轮如何推进

执行顺序为：

**已选热点集合 → 采集基本信息 → 本地网页候选人选 → 采集详情与后续 → 轻量二创 → 人工确认 → 发布核实 → 复盘调整。**

先让一条真实内容贯穿全程，再以小批次重复运行。定位研究期间可以同时试取少量素材、确认账号条件，避免选完方向才发现素材无法获得或账号条件不具备。

整条流程使用三层验收，各自记录进度：

| 验收层次 | 完成条件 | 不能由此推断的结论 |
| --- | --- | --- |
| 人工参与的流程跑通 | 真实素材经筛选、人选和整理后，在至少一个目标平台完成发布并核实 | 自动发布已完成，或内容具有持续商业价值 |
| 自动发布跑通 | 用户批准具体内容后，工具完成目标平台的发布操作，并核实实际作品状态 | 另一平台、另一种内容格式也已验证，或可以长期无人值守 |
| 内容经营获得初步证据 | 连续记录选用、耗时和作品表现，能判断哪些题材值得继续试验 | 新号必然盈利，或已经形成可复制的账号矩阵 |

首个成功平台用于尽早取得反馈。公众号和头条仍需分别验收；其中一项未完成时，应明确下一步和阻塞原因，不能把它从目标中删去。

## 四 账号定位怎样确定

### 要回答的五个问题

每个定位必须说明：谁会反复看，什么处境或兴趣把这些人连接起来，哪些素材容易让他们停留，他们有什么话想说，以及这些素材能否以低成本持续获得。

“社会类”“娱乐类”可作为研究范围，最终定位还需要落到可执行的筛选条件。第一轮不要求把账号名称、头像、装修和完整品牌方案全部做完。

### 第一批研究任务

1. 提出不超过3个定位假设，每个写明目标人群、核心场景、主要吸引力和素材形式。社会生活方向至少纳入比较；其他假设由样本支持，不默认等于第二类账号。
2. 两个平台合计寻找约6至8个对标账号，尽量各有3至4个；优先近30天仍更新、能查看连续作品的账号。条件允许时纳入规模较小的账号。
3. 每个账号看约5篇连续近期作品，首批总量约30至40篇，同时保留普通表现作品。不要只挑高阅读截图或单篇爆款。
4. 每个定位试找3至5条真实素材，检查能否找到来源、取得内容、理解背景，并估计整理成本。
5. 输出一份比较结论：推荐先试哪个、证据是什么、暂不选其余方向的理由、哪些假设需要实发验证。

首轮研究控制为一批有边界的调查。若部分账号数据不可见，交付可核验样本和对应缺口，继续用素材试采与小批发布补证据；不无限扩展研究，也不为凑数量虚构样本。

### 每篇对标作品记录什么

- 平台、账号、作品链接、标题、发布时间、采样时间。
- 作品主要面向谁、具体场景、吸引点及内容形式。
- 能看到的阅读、点赞、评论等数值，以及它们各自的统计口径。不可见项留空。
- 内容如何组织：原始素材占多少、作者补充什么、是否有反差、后续或讨论点。
- 素材可能来自哪里、我们是否实际找到、整理工作大约有多少。

优先用平台或研究机构的原始报告理解平台环境，用连续真实作品判断内容做法，用实际试采判断供给。全平台用户画像只能帮助缩小研究范围，不能直接证明某个新账号的题材一定有效。旧数据标注年份；不同平台的指标不直接混算。

### 定位交付卡

定位确定后至少保存：目标人群、核心场景、读者停留理由、纳入题材、暂不纳入题材、主要内容形式、可用来源、3条真实适配素材、定位版本和本轮验证的问题。

由助手给出有依据的推荐，用户作最终选择。账号命名和视觉包装只做到不影响开通与发布的程度。

## 五 素材与话题怎样收集

### 来源必须支持实际选题

来源可以是新闻与事件线索、持续更新的内容账号、公开话题讨论、图片或视频素材集合等。热榜主要提供话题入口，还要找到足以理解事件的实际材料。对标账号和素材来源分别记录：能观察其选题，不代表已经能够取得所需素材。

第一轮只试2至3个来源，先验证至少1个能实际取得所需素材的来源，并保留替代获取办法。持续供给能力在后续重复轮次中验证，单批成功不等于已经稳定。选择顺序由素材产出和获取成本决定，不强制使用 RSS、爬虫或某个聚合工具。

### 每个来源的验证记录

| 项目 | 记录内容 |
| --- | --- |
| 来源与覆盖 | 名称、入口、主要题材、适用账号 |
| 获取方式 | 人工浏览、现有订阅、公开接口或已有工具，以及本次实际使用的方法 |
| 取得内容 | 标题、正文、图片、视频、互动信息分别能拿到什么 |
| 时间 | 来源标注的时间、事件发生时间、收集时间；无法确认的单独标注 |
| 样本与结果 | 真实样本链接、成功条数、失败情况、是否有重复或缺失 |
| 成本 | 人工耗时、是否依赖登录、是否产生额外费用 |
| 后续处理 | 继续使用、暂缓、替换或补充另一来源 |

### 素材最低记录内容

基本采集保留可引用编号、标题、事件时间、来源链接，以及来源提供时的封面；记录来源和采样时间以便追溯。事件时间缺失时标未知，不以采样时间或报道发布时间代替。选中后才补充简要事实、人物场景、媒体位置和已知缺口。

优先保留链接和必要的预览信息；决定采用后再准备发布所需文件，避免一开始大量下载。只能看到标题而无法查看内容时，记为线索，不冒充素材齐全。

时效性事件和可长期使用的趣味素材分别处理。历史内容必须保留原始时间，不能因为重新收集就标成新发生。时间不明、关键事实相互矛盾或缺失重要前后文的素材，进入待核实项；读者对事件有不同立场本身不影响成为候选。

首轮不建立全年热点库。只有当前选题明确需要历史对照时，才针对性补充历史素材。

## 六 怎样筛成值得用户看的候选

### 先做基本筛查

基本候选先根据已取得标题、时间、链接及可得封面判断是否值得用户选择，并标明缺项；不要求提前读取正文或判断完整事实。选中后再核实主要内容、背景与整理可行性，无法判断的留待核实，不冒充可发布内容。

去重目标是避免同一事件或核心画面反复推送，并保留重要后续和不同来源。当前工作台只对同一来源的同一身份精确复用；跨来源相同标题仅提示可能重复，须人工核对，尚未实现语义去重或自动识别后续。

### 选中后判断为什么可能有人看

对每条候选用短句说明以下维度，不先做复杂评分模型：

| 维度 | 具体判断 |
| --- | --- |
| 人群适配 | 哪一类读者会觉得与自己有关 |
| 第一眼吸引力 | 是画面、冲突、反差、悬念、好奇还是熟悉场景 |
| 参与空间 | 读者可能分享什么经历、补充什么、对哪一点产生不同判断 |
| 素材完整度 | 是否有足够画面和前后文，是否有结果或后续 |
| 整理成本 | 还要找多少信息、处理多少素材、用户大约要花多少时间 |
| 时效与重复 | 现在发是否合适，是否与本账号近期内容过于相似 |

先用“优先看、备选、待核实、淘汰”排序。若之后引入分数，分数只辅助排序，权重由实际采用和发布反馈逐步调整。

### 每次给用户的候选卡

每轮采集当前可得的榜单基本信息，在本地网页供用户筛选；候选至少包含：

- 编号、标题、来源、事件时间（未知则标明）和采样时间。
- 来源链接，以及有则显示的封面。
- 用户决定：采用、淘汰、待定；需要时补一句原因。

来源失败及缺项如实记录；不为凑数虚构内容。适配人群、表达角度、详情和整理工作量在选中后再研究。

## 七 人如何参与

用户主要参与候选取舍和内容确认。助手承担收集、去重、选后详情研究、材料整理、执行记录及已授权的重复操作。选中候选仅授权进入详情和内容准备；完整二创内容须独立人工确认，实质改稿后原确认失效。

| 环节 | 助手的产出与责任 | 用户参与 |
| --- | --- | --- |
| 定位 | 真实样本、比较和明确推荐 | 选择首个定位或指出不接受的部分 |
| 日常选题 | 可直接查看的少量候选及推荐理由 | 用编号选择、淘汰或保留待定 |
| 内容准备 | 素材、简短文本、标题及平台适配 | 检查表达是否符合偏好，提出必要修改 |
| 发布 | 按已明确的内容、平台和时间执行并核实 | 首次登录、处理必要的人机交互，确认对外发布范围 |
| 复盘 | 用数据说明哪个环节值得调整 | 对重要定位变更和投入作决定 |

用户在本地网页选择采用、淘汰或待定；批次、编号和决定需持久保存，防止重跑或切换会话后丢失。

淘汰原因可简单记录为人群不符、没兴趣、太旧、太常见、材料不足、加工太费时或其他。原因用于更新下一轮筛选，避免每天推回同类无效候选。

候选“选中”意味着进入详情采集和内容准备，不等于发布确认。实际发布还须用户对完整内容独立确认并在既有授权范围内操作，实质改稿后重新确认。

## 八 选中素材怎样变成可发布内容

以素材本身和少量必要表达为主。根据实际内容选择单一事件整理、图片组配短评、视频配简短说明、多个相关素材的小合集等形式，不要求全部写成长文章。

每篇发布内容至少包含：

1. 对应候选编号、目标账号与平台。
2. 一个主标题；需要比较时再提供少量备选标题。
3. 交代人物、场景、前因后果所必需的简短文字。
4. 实际使用的图片、GIF或视频，以及顺序、封面和必要说明。
5. 与内容匹配的作者观点、补充或讨论问题；并非每篇都必须提问。
6. 来源及尚待核实的信息，供用户检查。
7. 已确认版本和当前状态。

AI 可用于概括、分类、整理和文本修改；首轮可在现有 Codex 对话内按批次完成这些工作，不预设后台能无人值守调用，也不把额外模型 API 作为依赖。

同一素材能否同时用于两个平台由适配结果决定，标题、文本长度、图片顺序和视频呈现可以不同。若GIF或视频无法按预期展示，记录实际限制并选择可用形式，不为了保持同一种格式投入大量开发。

事实、引述和评论保持可区分，保留关键前后文；有不同立场的材料可以用于讨论，不能把未经核实的猜测改写成已经发生的事实。

## 九 发布如何推进和验收

### 先看目标账号的实际条件

两个平台分别记录账号、准备发布的内容形式、可用入口和实际工具能力。使用现成工具时，先验证真实账号中的操作结果，再决定是否纳入日常流程。

第一次发布可以由用户手动完成，也可以在条件具备时直接测试自动操作。手动过程用于确认内容形式和完整步骤，记录哪些步骤值得替换。自动化优先补掉稳定、重复且耗时的操作。

### 发布状态与执行方式分别记录

| 状态 | 认定依据 |
| --- | --- |
| 待用户确认 | 内容包已准备，尚未在既有授权范围内确认发布 |
| 待发布 | 具体内容、账号和必要条件已具备 |
| 已保存草稿 | 平台草稿箱中存在对应内容，已核对标题与素材 |
| 已提交或平台处理中 | 平台已接收提交，但尚未核实实际发布 |
| 已发布并核实 | 目标账号中存在对应作品，可回读核对标题、素材和时间，保存可用链接或作品标识 |
| 失败或待核实 | 保留实际错误或不确定状态，并明确下一步 |

每次额外标注“手动、部分自动、自动”。点击按钮、调用成功、队列任务结束、模拟测试通过，都不能单独作为发布成功证据。

图文、GIF和视频按本轮实际采用的形式验证。公众号图文验证成功不代表头条图文成功，也不代表该平台视频已验证；无需为了首轮验收强制测试所有格式。

### 失败与恢复

首次失败保留原因和已发生的操作。登录过期或需要用户交互时，停在具体节点并说明需要用户做什么。来源或工具暂不可用时，可切换已有替代方法并记录额外人工成本。

提交结果不确定时先查平台实际作品或草稿，再决定是否重试，避免重复发布。自动发布失败但手动发布成功时，两种结果都保留，自动化任务继续待完成。

自动发布的首轮验收至少覆盖：用户确认的一篇真实内容、目标平台的真实操作、成功后回读，以及失败时如何识别和恢复。公众号和头条分别记录结论。

## 十 发布后怎样判断值不值得继续

首轮同时记录流程是否划算和内容是否获得反馈。不能只看素材采集了多少，也不能只看最好的一篇。

| 维度 | 指标或观察 | 用途 |
| --- | --- | --- |
| 素材供给 | 每轮实际查看数、候选数、可用素材缺口 | 来源能否持续供给 |
| 候选质量 | 用户采用数、淘汰理由、采用数除以候选数 | 初筛是否贴近用户判断 |
| 执行成本 | 收集、挑选、整理、发布各花多少人工时间 | 哪一步最值得简化或自动化 |
| 实际产出 | 准备数、草稿数、发布数、各平台失败数 | 流程在哪一步损失成果 |
| 阅读与互动 | 平台实际提供的展示、阅读、点赞、评论、分享等 | 哪些素材和表达值得继续 |
| 账号积累 | 可见的关注变化、读者持续反馈 | 是否在形成相对稳定的人群 |
| 收益与支出 | 后台可见收益、实际新增费用、人工时间 | 是否值得继续投入 |

不可见指标留空并注明，不能填成0。没有曝光量就不估算点击率，没有收益权限或收益数据就不推算收入。评论数量与评论内容一起看，区分读者参与话题、补充事实和对内容本身的不满。

尽量在相近的发布后时间点记录，例如约24小时和72小时；这是暂定观察窗口，错过时保存真实采样时间。比较以同平台、相同或相近形式的内容为主，不直接把两个平台的阅读数当同一指标排序。

第一轮建议做3至5轮小批验证，再决定是否继续一个7天观察周期。样本少时只能提出下一轮假设，不得把偶然高阅读当作定位成功。每次重点调整一个主要因素，例如来源、人群范围或内容组织方式，保留修改理由。

## 十二 一轮日常执行的样子

初始允许人工发起，现已实跑[轻量脚本](../scripts/collect_hot_candidates.py)采集热点，不预设已经有无人值守定时任务。脚本默认抓取、保存、按标题去重并取前10条，尚不自动判断适宜性；本轮人工复核名单由人选10个话题ID，正文核验、角度及样例均人工辅助。后续验证T9A；一次发起与定时运行分别记录，只有实际按约定时间触发并产出候选，才能称为每日定时自动运行。电脑在线条件和失败通知方式在验证时明确。

1. 使用现有工具或轻量脚本采集热点和素材，处理重复与缺失，筛出候选。
2. 用户在本地网页查看并选择候选，记录实际参与时间。
3. 对选中项采集详情和必要后续，助手轻量整理，完整内容须独立人工确认；实质改稿后重新确认。
4. 账号条件具备后，通过已验证方式发布并回读；登录、素材上传和平台等待分开记录。
5. 记录本轮采用、淘汰和执行情况，补看前轮作品表现。

此前每周2–3条、单条36–59分钟的初步方案已撤回。用户参与每天最多1小时，必要事实与权利未核清则暂停；账号开通及工具等待分别记录，发布频次和单位时间成本由实跑测量。

## 十四 什么情况下才投入工具开发

用户已明确授权实现本地网页工作台，用于五个热榜的基本信息采集与人工筛选；历史只留接入口，定时配置先关闭，目标机器和操作系统待确定。其他工具投入仍按实际问题选择最小改进。

| 真实问题 | 优先尝试的处理 |
| --- | --- |
| 重复打开相同来源，手动摘录耗时 | 现成订阅、导出或小型采集脚本 |
| 同一事件频繁进入候选 | 简单的去重记录或脚本 |
| 图片顺序、格式转换反复操作 | 现有批处理工具或模板 |
| 同一发布步骤稳定重复 | 先实测已有发布工具，再补必要的操作自动化 |
| 多批候选难查、多个账号状态混乱 | 先统一文件和状态；仍影响执行时再评估专用界面 |

本次工作台按用户授权实施；真实耗时和节约量尚未测量，以真实任务验收。其他开发任务继续说明问题、成本和验收依据。

本轮已授权本地网页工作台；不因此扩展为容器、复杂评分服务或全自动文章生成平台。定时任务未在当前机器创建，未来目标操作系统尚未确定。

## 十五 常见偏离与处理

| 现象 | 处理方式 |
| --- | --- |
| 调查越来越多，始终没选题 | 收拢到一批真实样本，给出推荐和不足，进入小批验证 |
| 收集很多但用户不选 | 看淘汰理由，调整定位、来源或筛选，避免单纯扩大抓取量 |
| 内容可看但加工太费时 | 换素材类型、缩短表达、降低本轮篇数，记录具体耗时 |
| 流程顺畅但作品没有反馈 | 检查题材、人群、发布条件和表达，保持小样本试验，不用增加系统功能替代内容调整 |
| 工具只能存草稿 | 如实记录草稿能力，继续验证真实发布步骤 |
| 某平台暂时无法完成 | 保留该平台未完成任务，继续已具备条件的平台并安排恢复步骤 |
| 软件开发逐渐变成主工作 | 回到真实阻塞和节约时间证据，暂停无直接收益的功能扩展 |
| 进入下一轮又忘了先前取舍 | 从上一轮人选结果、规则版本和复盘继续，避免重复询问和重复研究 |
