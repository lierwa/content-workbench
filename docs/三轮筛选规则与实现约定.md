# 各栏目三轮筛选规则与实现约定

更新：2026-11-01。当前设计以 [内容经营任务书](内容经营任务书.md) 为总入口；池、版本和续作机制见 [开发实施说明](开发实施说明.md)。实现与真实结果见 [本轮验收记录](栏目线实现验收-20261101.md)。

## 1. 先限定栏目，再选内容

每轮确定 line_id、内容形式、来源名单、时间范围、选稿模式与规则版本。自动运行使用配置的目标账号；手动选题尚未选账号时保留栏目合格候选，开始制作选账号后再检查该账号的重复与占用。程序按来源、时间和处理记录取候选，题材是否适合由本线选稿判断，不新增全池分类或关键词硬过滤。

输入包括需处理的新增、变化、未完成项，以及仍有效的已通过候选；指定目标账号时排除该账号已发布或被其他作品占用的项，不能按任一账号已用就全局隐藏。恢复原作品时沿用自己的选题快照。已通过候选复用已有核实，继续参与本次取舍，不能只看本轮刚采到的内容。期次定位作品，候选按本线消息有效期取；晚入池或上一轮没用，不因换期自动失去资格。

候选只从本线发现来源取；补证只用本线允许的补证来源。来源合格不等于内容合格，不能把共享池中其他栏目允许的事实自动混进本线。

## 2. 本线内归组

以实际事件关联报道，不靠完全相同标题或关键词数量。人物相同但事件不同的分开；同事件的进展、回应和细节保留关系与全部合格 refs。转载合并重复信息，保留实际出品方和来源链，不算多份独立证据。

带入本线有效期内已处理事件的短记录，包括通过、材料不足、淘汰及近期采用项。新报道既可能只是重复，也可能补齐旧缺口或带来新进展；不能只与已发布内容比较。

归组沿用运行记录，不建立永久事件库。判断复用须核对整组成员及版本、栏目规则和实际材料；相关新报道改变依据后重新判断受影响部分。无法判断是否同事件时先分开保留，不物理删除线索。

## 3. 三个阶段共用执行程序，判断规则按栏目独立保存

每个栏目都具备初筛、二筛、正文三筛。`rules` 定义栏目定位与范围；`screening_rules.initial/selection/verification` 分别保存三个阶段的独立规则。新建必须填全，不能依赖隐藏的热点账号提示词。模式提供可编辑模板和输出结构，不替代栏目自己的标准。

| 阶段 | 热点精选 | 科技简报 |
| --- | --- | --- |
| 初筛 | 有具体事件及普通读者关切；排除无看点复述、广告和旧闻 | 有具体科技新增消息；排除促销、旧闻、空泛预测和无实质变化的版本更新 |
| 二筛 | 比较看点、读者关联和可展开的独立文章角度，选本轮最值得取材的少数 | 比较新增信息、实际影响、读者相关性和整期主题，选少量消息；不要求争议、情绪或长文角度 |
| 三筛 | 用正文检验主线事实、看点和写作角度；只能平庸复述的内容可以被推翻 | 核实消息时间、变化和实际状态，区分计划、测试与已实现；每条能支撑准确短讯即可 |

新栏目选择适用模式并填写自己的标准，不复制整套流程、不做通用编排器。娱乐等栏目不是把名称换掉后照用商业或热点单篇 prompt。

### 热点精选的三筛

| 阶段 | 使用材料 | 判断 |
| --- | --- | --- |
| 初筛 | 合格标题、现成摘要、时间与来源 | 是否有具体看点，值得进一步比较 |
| 二筛 | 初筛晋级项与仍有效的既有候选 | 比较后确定本轮实际取材名单；未入选的内容不进入正文读取 |
| 三筛 | 实际正文与前轮判断 | 核实看点、核心事实及展开价值，决定是否值得写 |

正文在二筛通过后获取；已有且未变的核实结果直接复用。初筛、二筛可以共用一次请求，三轮是判断深度，不是调用次数。

[八项动机](筛选规则.md)只用于解释适用的热点选题，标签可以为空，不打标签总分；科技简报不套用这些标签。没有最低入选数量或晋级比例。`max_candidates` 是页面可见的单轮取材上限（1–10），当前热点 2、科技 5；选 0 个也正常。二筛必须完成真实比较，不能先放行几十个再排队读取。超限结果整体拒绝，程序不截断为前 N 个冒充筛选成功。

### 集合选编

初筛先判断是否属于本栏目的具体新增消息，二筛再按信息价值、题材一致性和整期搭配选条目，新旧有效候选一起比较。前两筛可以合并调用但分别保存结论，数据量大时分段初筛、统一二筛；不表示每个阶段都必须调用一次模型。

入选后读取实际报道，核实拟写摘要的事实、时间和来源；不足则补证或移出本期。每条不必能写成长文，不要求冲突、站队或强情绪。整篇仍需独立审稿；没有合格条目就不出稿，不凑条数。

## 4. 判断与输出

各阶段保留 stage、decision、reason、evidence、unknowns、输入与规则版本及整组依据。decision 为 advance、drop、insufficient、deferred；二筛 deferred 持久化为 `not_selected`，界面显示“本轮未选”。advance 只代表当前阶段通过。只有当前二筛规则对应的入选项、且数量未超过本栏上限，才可以启动正文读取。核实阶段记录逐来源 coverage。

drop 只表示内容不适合。合格但本期没选中、制作未轮到或运行预算用尽，继续保留通过或待办状态；本轮取舍与优先顺序另记，不能把相对排名低缓存成永久淘汰。

dimensions 是适用维度的一句 judgment 与 evidence，不是分数。热点用看点、参与、角度、成本及正文核实维度；集合用本期相关性、信息价值、重复与事实充分性。成本记录制作难度，不能替代事实质量和栏目适配。

程序检查输入 ID 去向、枚举、重复键、引用范围与逐字引文、正文哈希、排序和具体理由。结构通过不能证明语义正确，也不能用分值或标签反推 decision。

正文可以推翻前面的判断。主线不成立则淘汰；核心证据确实缺失则材料不足。未读全文不是普遍淘汰理由，正常取材能解决的缺口先取材。核验范围以拟写主张为准；个案不强求统计代表性，未核实的非主线细节不写入稿件。coverage 区分支持、重复与未取得，标题和搜索摘要不能冒充正文证据。

## 5. 原帖、参考报道与材料复用

entry_url 保留采集入口；original_url 只填写实际核实对应帖子。原帖不等于首发，知乎问题和实际引用回答保留具体关系。

热榜或搜索聚合入口没有唯一原帖时，经核实属于同一事件且支撑主线的实际报道可作 reference 材料。保存实际 URL 和对应依据，不伪装原帖，不因 original 为空而一票否决。不默认选择首个搜索结果，不按标题或发布时间完全相同判断对应。

已读正文立即保存 material_id、role、origin_ref、URL、读取时间、内容哈希和 content_ref。创作复用已读正文，不因切平台重复抓取；搜索入口和最终报道的关系进入缓存识别。没有正文时记录具体缺口或读取失败，避免调用模型判断“没有材料”。

新正文同时更新内容、哈希、路径和关联来源；损坏材料不得支撑当前结论。仅重做受影响的事件与阶段，reader_version 变化不强制重跑未受影响的选稿。

缓存按阶段拆开：初筛依赖本栏定位、初筛规则和整组输入；二筛额外依赖全部比较候选、二筛规则与取材上限；三筛依赖三筛规则、实际正文和选定主张。仅修改三筛规则时，复用未变化的归组、前两筛和正文，只重新核实。完整输入、规则或提示词不匹配的历史模型结果不能按 ID 硬套。改创作要求、账号和调度时间不改变事实核验结论。

## 6. 退出、继续与消耗

结果只影响本线及形式，不能全局删除池内线索。过期退出该线候选，仍供其他有效用途取用；淘汰在同一依据下不重复筛。材料不足可由新的相关报道补齐；临时取材失败保留待办，到下次已配置运行或明确继续时再尝试，到期退出。

采用按目标账号和形式检查已发布及仍占用的作品，防止换栏目重复发同一事实；单篇与集合可分别使用，新进展另判。明确取消或移出未发布条目后释放本作品占用，发布结果未知仍保留；释放不等于重新判为通过。作品占用、期次和重试规则见开发说明，不另建一套使用状态。

每轮保存实际输入快照与固定时间范围，中断继续原 run_id 的未完成部分，不能重新计算窗口而漏项。依据变化时旧结果留历史，不覆盖新版；无自动无限重试。

记录实际输入/输出 token、缓存、耗时与失败；未知不记零，不凭字符数估算账单。执行范围以会话授权和开发实施说明为准，不新增测试文件。新规则完整输入、连续调度和双平台存稿的实际验证单独记入 [全流程验收](全流程验收-20261101.md)，旧批次成绩只保留为历史。
