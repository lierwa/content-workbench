# 栏目线与线索池开发说明

更新：2026-11-01。本文记录最小实现及设计约定，业务目标以 [内容经营任务书](内容经营任务书.md) 为准。已获准开发、使用全新内容和业务 AI 验证，平台仅保存草稿；实际完成范围见 [本轮验收记录](栏目线实现验收-20261101.md)。

## 0. 本轮必须交付什么

平台草稿的新建、更新、恢复以 [平台草稿流程](平台草稿流程.md) 为统一约定。已有远端 ID 必须进入更新或恢复，不能因失败转去新建；操作与版本绑定并持久化，重新打开核验通过才算完成。配图独立于已审定文字：先读原文多图，再按同事件报道补图，均无合适图片时使用 `assets/covers/fallback.json` 指定的项目公共封面；正文不插入兜底图。选图结果跨平台与重启复用。

**当前设计与界面以 [架构与界面设计](架构与界面设计.md) 为准；本轮来源扩充、线索池和业务接续进度见 [全流程验收](全流程验收-20261101.md)，此前 UI 证据见 [界面验收](架构与界面验收-20261101.md)。** 下表保留前一轮工作范围；长期连续运行与公开发表不得由 UI 验收推定。

| 任务 | 必须交付的结果 | 目前还缺什么 |
| --- | --- | --- |
| 1. 来源与栏目 | 维护可扩展的采集清单，逐源写明入口、服务栏目、取得字段、采集安排和失败处理；栏目明确题材、时效、筛选方式、单篇/集合及目标账号。入选来源实际接通，不能用研究过的网站充数 | 15 个渠道实际采集 479 条；科技栏目 6 家媒体。两源连续采集 4 个周期去重通过，正文受限情况单列于来源清单 |

来源清单持续可扩展，先明确用途再接入。当前实际接入 15 个渠道，四个热榜保留，百度按第 6 节取材；科技使用 6 家媒体。36氪 RSS 已接入，正文若返回安全检测页则记未取得，不能将其作为正文依据；财联社电报仍不计入已接入数量。具体入口、栏目及读取边界见来源清单。新增来源不自动增加栏目，娱乐仍是可配置的栏目示例。

48/24 小时有效期由栏目配置控制。当前正式全量采集不设置条数上限，旧版隐藏的每次 40 条不再作为现状。样本限制须与日常采集配置分开，不能由页面硬编码决定一次业务消耗。

执行顺序：先明确本次来源接入和页面操作规则，再补池与筛选的实际缺口，然后接通两种制作方式，最后验证运行恢复和双平台草稿。已有二创、编辑器、账号和平台流程继续复用，只修直接阻塞。**五项全部有验收证据才算本轮完成；未完成、结果未知或只写了交接文档都不触发关机。**

single_pass/workspace.py 接管采集与按栏目筛选，pool.sqlite3 保存共享线索和栏目记录。server.App 仅复用为运行快照的读取视图；current.json 不再限制当前候选。采集和各栏目分别运行。

### 本地浏览器连接与恢复约定

- `platform-accounts/browser-control.json` 保存已经核实的端口、扩展实例、Chrome 程序路径和配置目录；本机为 17800 / efcdd407 / Default。清空业务数据必须保留它及账号、栏目配置。
- 工作台启动先检查已有服务。只有明确确认服务缺失，才由长运行工作台启动 `bsk daemon start --foreground --port <configured>` 子进程；有服务但端口或实例不同则明确报错，不停止未知服务。日志和状态分别保存在 `browser-runtime.log`、`browser-runtime-state.json`。
- 两平台固定动作由适配器执行，无逐步 AI 操作。平台队列串行完成写入和回读；采集、筛选和创作不因此改为全串行。取得浏览器锁前的失败不表示已经写入。
- 同一轮持久租约只复用原会话，每 30 秒保活；失去会话不自动换窗口。正常结束直接调用工具的会话停止并核对活动会话，清除本地租约；保存分组是否仍存在与会话释放分开记录，不逐个清理。
- 未知写入保留操作 ID、内容摘要、图片证据及原编辑页；只在账号和版本匹配后核验或原位续作。工具明确未执行且正文未变的输入可重试一次，未知效果不能盲重放。
- 三筛完整来源覆盖决定后续检查范围：supported 主线来源控制时效，supported / duplicate 来源参与占用；unavailable 保留为排除证据。覆盖不完整则保守检查所有原来源。

本轮清库后六份新草稿和浏览器服务恢复证据见 [全流程验收的本轮记录](全流程验收-20261101.md)。截图超时与纯空闲保活验证的未通过范围也在其中列明，不能以服务连接成功代替所有页面操作可用。

## 2. 栏目与来源配置

栏目用稳定 line_id，保存名称、允许来源、题材范围、时间规则、选稿要求、内容形式、筛选/发布安排及账号。两种模式均执行初筛、二筛和正文三筛；热点单篇与消息简报使用各自标准，不支持任意步骤编排。配置通过版本化栏目 API 保存在 data/column-config.json；页面可以创建栏目、选择独立渠道、填写筛选和创作规则。初次读取原 columns.json 默认值，首次修改后持久化。

来源配置保存稳定 source_id、实际栏目/账号/榜单入口、已有适配方式、采集间隔及启用状态。来源更新节奏与栏目筛选/发布节奏独立；RSS 返回条数不等于固定保存小时数。

集合贴先限定来源名单，并把题材边界写进选稿要求。程序只按来源、时间和处理记录取候选，题材适配交本线选稿判断；不按关键词硬排除，也不新增全池分类。选题入口与可补证来源范围分别写清。缺少来源、时间规则或选稿要求不得自动启用；不虚构统一的采集频次、样本数或晋级配额。

一条栏目线可以选择单篇或集合；同时启用两种形式时，用 format 区分选稿记录，材料共用。

### 栏目三轮规则与取材约束

栏目 API 必须保存 `screening_rules.initial/selection/verification`，各 1–10000 字，另存 `max_candidates`（整数 1–10）。`rules` 为栏目定位与范围，`writing_rules` 为创作要求。当前热点单轮最多取材 2 个事件，科技最多 5 个；可以为零，不凑数量。完整规则与两栏目的判断对照见 [三轮筛选约定](三轮筛选规则与实现约定.md)。

二筛的 advance 只表示本轮实际取材名单。接口检查全部输入 ID、判断依据、优先级和数量后一次落盘；超限整体拒绝，不先写入部分结果。启动 reader 前再次检查当前二筛规则哈希和数量。deferred 保存为本轮未选，不伪装淘汰或材料不足。

初筛、二筛、三筛分别保存 `stage_hashes`；分组成员及版本不变时复用归组。仅三筛规则改变时，前两筛与已读正文均复用，只重核正文。二筛改变时重新比较本轮全部合格候选。模型成功结果的恢复须匹配完整提示词，不能只凭事件 ID。实际正文及时落盘；部分来源读取成功后不会因其他来源失败而全部重新读取。

模型只承担归组、内容判断、写作和独立审稿。采集、缓存核对、排版、平台导航、存草稿、回读和恢复走固定程序。共享一篇作品的写作与审稿，不按平台重复生成；新作品只组合当前栏目和所选账号要求，不读首个账号作为全局标准。

## 3. 新增两张表即可

### pool_items：长期线索

| 字段组 | 用途 |
| --- | --- |
| id、source_id、source_key、entry_url | 跨采集批次的稳定身份，保留真实入口 |
| title、summary、published_at、event_time | 列表已有内容；未知时间为空，不编造摘要 |
| first_seen_at、last_seen_at、metrics | 发现时间与观测热度；不能冒充新闻发生时间 |
| version、fingerprint、snapshot_ref | 列表内容版本、比较摘要、原始快照位置 |

同来源有稳定编号时按 source_id + source_key 唯一，否则按 source_id + 规范链接唯一。规范化只去明确的跟踪部分，保留帖子、回答和查询身份参数。不同来源同标题不据此删除。

标题、现成摘要、有效链接、发布时间等判断依据变化才增加 version；仅再次出现、位次或热度变化只更新观测字段。旧输入快照放在已有执行目录，不增加版本历史表。

正文不在入池时批量抓取。本线选稿后的取材沿用现有材料文件、哈希和引用关系；正文变更使受影响的事实核验结论失效，未受影响的选稿判断复用。

### line_records：栏目处理记录

唯一键为 line_id + format + item_id。保存已处理版本、规则版本、basis_hash、run_id/result_ref、阶段、decision、理由和处理时间。decision 为 advance、drop、insufficient、deferred；二筛 deferred 对应阶段 not_selected（本轮未选），不会自动读取正文；advance 必须结合阶段理解，初筛或二筛晋级仍有待办，不能当成整线筛选完成。

basis_hash 绑定本次事件组的全部成员及版本、栏目规则和本阶段实际材料；分组和依据清单沿用运行 JSON。新增相关报道也会改变依据，不能只检查某一条记录自身的 version。整组结果指向同一 result_ref，并在短事务中校验版本、一起写回，不新增事件表。

完整逐轮输出、临时事件归组和旧判断沿用现有运行文件，不复制出全局事件表。作品采用及平台状态沿用生产记录，通过 line_id、format、run_id、稳定 item_id 和材料版本关联。

没有“整条线索全局已筛/已用”的字段。一个栏目的淘汰不能影响其他栏目，集合中的采用不能阻止单篇制作。

内容是否适合，与本轮是否选用分别记录。drop 只表示当前依据下内容不适合；因本期已有更优选题、制作排期或运行预算未轮到，不得写成 drop。已通过项继续待选，未完成项保留阶段；优先顺序和本期选用记录归本轮运行或作品，不当成永久判断缓存。

## 4. 两个独立动作

### 采集

正常获取列表 → 解析 → 事务中新增/更新 pool_items → 保存本源成功或失败记录。先落库再推进采集进度；空响应、解析失败和正常无新增分别记录。重复执行不重复建线索。数据库事务仅用于短时读写，不能持有写锁等待网络、浏览器或模型。

复用一个本地服务做简单定时检查，不引入消息中间件。单源失败不阻断其他源；采集不拿整个筛选流程的忙碌锁。本轮已启动本地服务验证；sources 和 lines 的 interval_minutes 均为 null，未启用持续采集。

### 按栏目筛选

1. 取得 line_id、format、规则版本和本轮时间范围。查询分两部分：需处理的新增/变化/未完成项，以及仍有效的已通过候选。自动运行已有目标账号时，排除该账号已发布及其他作品占用的项；手动选题尚未选账号时，不能因一个账号用过就隐藏整条候选，开始制作选择账号后再检查占用与重复。恢复原作品沿用自己的选题快照。占用和发布从作品记录判断，不能跨账号共用一个“已用”标记。
2. 保留有效期内已处理事件的短记录作关联上下文，包括已通过、材料不足、淘汰和近期已采用项；不重复取旧正文。新报道能补齐旧事件时合并本次判断，不能只与已发布内容比较。
3. 一致读取并保存实际标题、摘要、时间、refs、版本、既有结果和栏目配置，形成 run_id 输入快照；只存 ID 后再读取可变的池内容不算冻结。按本线独立的三阶段规则执行初筛、二筛和正文三筛。
4. 依据未变的事实核验复用；新旧候选仍一起做本次取舍和排序。分块执行时，初筛晋级、待取材及失败项都保留各自阶段，不把未完成当完成，不丢掉已核实但未用的候选。
5. 写回时检查规则与相关输入版本；变化时旧结果仅留历史。每条线先只运行一个选稿任务，采集独立进行。中断恢复原 run_id 已完成部分；依据变化的项另行处理，不覆盖新版。

时间规则分别确定消息有效期、本期截稿点及重复比较范围。消息有效期可以是滚动区间或明确的日历区间；每轮冻结该区间内的候选，不用“上次筛到的时间”作为新的查询下限。晚入池、上一轮未用的消息，只要仍在本线有效期内就继续参与；换一期本身不等于过期。期次定位作品，不能代替候选有效期。

候选时效先按本条报道的已知发布时间计算；事件发生时间留作判断，后续新报道不能因起因较早被自动排除。首次发现时间仅在发布时间未知时用于查找待办，入稿前仍须核实新近性；重复抓取不刷新有效期。同一次运行重试沿用冻结范围，新增或晚到内容留给下一次选稿；恢复不延长新闻有效期，出稿前仍复核时效，不包装过期消息为当前新闻。

规则或来源配置改变，只重看受影响的本线有效候选；不全池重筛，不清空其他线。采集/筛选间隔、目标账号和自动存稿开关不属于选稿事实依据，改变它们不使既有事实核验缓存失效。预算、模型配置和重试按实际配置及授权范围，不用旧文档数值覆盖。

## 5. 去重和退出

| 情况 | 最小处理 |
| --- | --- |
| 同来源同一内容再次采到 | 更新原记录，稳定 item_id 不变 |
| 跨来源转载、同一事件多篇报道 | 在本线筛选时语义归组，全部合格来源保留；转载不算独立互证 |
| 与已有事件相似 | 结合本线有效期内已处理事件和近期采用短记录，识别重复、新进展和补证；初次未采用也要能关联 |
| 同一事件有后续 | 新报道正常入池，本次筛选判断新增事实；不建立自动追踪服务 |
| 误合并或无法判断 | 分开保留；运行内分组可纠正，不能物理删掉原线索 |

候选只从本线发现来源取，补证只用本线允许的补证来源；不能从共享池混入被排除来源的标题或事实。集合来源若一页包含多条消息，须保留可定位的条目引用；无法拆清时先作为线索，不当成一个已核实事件。

退出规则直接由栏目查询和处理记录完成：

- drop：内容不适合本线及形式，该事件依据未变时不重复判断；相关新报道或规则改变后才重看。本期没选中、未轮到不属于 drop。
- insufficient：保留缺口；新的相关报道可以触发补证，不能只等原 URL 更新或人工点击。临时取材失败留在待办，下一次已配置运行或明确继续再尝试，不在本次无限重试；到期退出活跃候选。
- 过期：退出相应栏目的候选范围，仍供其他有效栏目或进行中的作品取用；重复抓取不续期，新发布的转载也须核实实际消息时间，不能当作新进展。
- 制作占用与已发布：引用关系记在作品上。开始制作只占用，确认发布才记已发布；采用前比较目标账号同形式近期已发布及仍占用的作品，避免换栏目重复发同一事实。明确取消制作或从集合移出的未发布条目释放本作品的占用；失败待续、保存草稿和发布结果未知均不自动释放。释放不改变筛选结论，仍有效且已通过的项才回到待选；不影响其他作品的占用或已发布记录。集合与单篇可分别使用，新进展另判。
- 无栏目再需要且无进行中的作品：退出活跃库存。初版不新增自动物理清理任务，作品引用材料继续保存。

新池不导入已要求清空的旧业务素材、草稿或判断。旧文档中的数字与稿件 ID 只作历史文字，不作初始化数据。

## 6. 栏目选稿、创作与集合

详细规则分别见 [栏目筛选约定](三轮筛选规则与实现约定.md) 和 [创作审稿](二创规则与独立审稿约定.md)。

热点精选线沿用初筛、二筛、三筛，二筛后取正文；三轮不代表三次调用或固定配额。集合线用一次短信息选编决定取材，取得正文核实后编排整篇，再独立审稿；不复制单篇的多轮横向比较。其他栏目选择适用模式及自己的题材、取舍标准。

已读正文保存 URL、读取时间、哈希、角色、origin_ref 和 content_ref，创作直接复用。实际参考报道可支撑事实；保留 reference 身份，不伪装榜单原帖。入口为搜索页不自动丢弃来源。程序提取实际搜索结果，AI 选待核实链接，程序读取正文后由本线事实核验判断事件关系；具体输入、输出和失败处理见 [百度取材规则](../sources/来源清单.md)。不能按第一个结果或完全相同标题决定。

集合稿保存固定 edition_id、栏目、时间范围、条目顺序及材料引用；进入创作时固定选题快照，晚到内容参加下一次选稿，不能直接塞入已审稿件；不要求每条先生成长文。整篇独立审稿检查主题、事实、重复、排序、标题兑现与表达。某条未通过可移出本期再审；没有合格条目就记录本期无稿，不填旧闻或发空稿。

同账号同栏目同形式同一期次只创建一份作品记录，重试复用原记录；账号内创建作品串行登记，已登记制作中的条目也参与去重，创作随后仍可并行。单篇同一选题快照的重复提交同样复用。取消或移出条目前确认不存在已发布或结果未知的平台动作；发布状态未知时保持占用并先回读，不能释放后重建。已取消作品不由定时任务自动恢复；其素材后续取用仍走正常选稿，不能立即循环重建同稿。占用、发布、释放沿用作品状态与条目引用，不加第三张池表。

标题/正文/实际取材/规则变化后重新判断审稿复用。文字、图片和平台回读分别记录；新证据影响尚未发布的主张时，稿件转为需要复核，不静默替换成稿。

| 用户要做什么 | 页面怎么响应 | 不能出现的结果 |

开始制作时检查目标账号重复与占用；已有自动安排则使用配置账号。公开发布遵循授权范围，本轮仅保存草稿，不在选题流程增加审批层。

## 8. 发布、实施与验收

目标是自动发帖，当前已有草稿流程继续复用；正式发布能力需按平台补齐并取得真实回读。作品是否已保存、审稿是否有效、是否实际发布分别记录。平台结果未知先核验原稿，不盲目新建或重发。

同步已审稿件由固定程序完成：核对账号和已有稿 → 写入标题、正文 → 上传并核对图片 → 设置摘要、封面和平台选项 → 保存 → 重新打开核对。用户一次发起，微信和头条分别记录进度与结果；这些步骤不调用写作或判断模型。AI 用于需要内容判断的选题、创作和审稿，不负责逐按钮指挥同步。

固定程序每步检查实际前置条件和结果。暂停后按原操作 ID、稿件版本和平台草稿恢复；已完成平台不随另一平台重跑。富文本替换必须先确认编辑器已清空，再粘贴并完整回读，不能只设置 DOM 选区后假定编辑器已同步。结果未知时先读取现状，不能直接重放上传或保存。需要临时逐步操作才能成功的路径，仍记作自动同步未验收。

实施任务及顺序以第 0 节为准。本轮停止在草稿；最终目标中的正式发布不能混入本轮验收，也不能因只验草稿而宣称自动公开发帖完成。

必要验收包括：重复入池不增副本；筛选不挡采集；栏目来源与流程隔离；已通过未用候选仍可选；初筛晋级不被误标完成；本期未选不被永久淘汰；换期不漏仍有效的晚到或待选项；取消制作释放占用但结果未知仍保留；新报道补齐旧事件；输入变更不覆盖新版；归档不影响其他线；同一期/同选题重试不重复建稿；集合主题与平台回读成立。用全新内容和获准范围验证，不新增测试文件、框架或额外样本，不因文档验收自动触发业务运行。

实际调用、token、首次失败和重跑见本轮验收记录。局部检查与完整平台验收分别记录；未取得双平台草稿回读前，不宣称端到端通过。

验收必须补齐以下实际证据；不要求每条另写测试文件：

| 检查 | 通过标准 |
| --- | --- |
| 来源与采集 | 最终清单中的来源均能实际取得基本信息并入池；失败来源单独可见，其他来源继续；明确哪些来源仍只是候选。一次可读不宣称长期完整覆盖 |
| 池与栏目 | 重采不增副本；采集不等待筛选；切栏目不串来源、结果或勾选；新的、晚到的和仍有效未用的内容都能进入下一轮；过期退出候选但证据不丢 |
| 判断与取材 | 热点二筛后取正文；集合选编后取正文；百度保留入口、AI 所选实际链接及正文对应依据。缺材料留具体原因，不能把失败自动当淘汰，也不能把搜索摘要当正文 |
| 使用与变更 | 同账号同形式的重复提交复用原作品；取消和移出只释放允许释放的条目；结果未知不释放。新证据或正文变化使受影响结论重新核实，旧运行不能覆盖新版 |
| 页面实际操作 | 在实际页面走通上表五条路径，包括无候选、采集中筛选、切栏目、返回、刷新、选稿、集合改序/移除、取消及失败后继续；交付真实页面截图，不拿设计示意当已实现界面 |
| 两种成稿 | 单篇一篇、集合一篇分别有事实依据并独立审稿通过；集合无重复/串题，修改条目后复审；标题、正文、图片、封面及来源可读可查 |
| 运行与恢复 | 以有边界的运行验证采集和栏目各自的安排，不能全部关闭后声称自动运行通过。完成一次中断恢复及重复触发，原任务续作且不重复稿件；依据未变不重复事实核验，必须重新调用时记录原因 |
| 平台与收尾 | 两篇内容各在两个目标账号保存：共四份草稿，逐份回读标题、完整正文、集合条目、图片/封面和账号；先查清原未知结果。清理本任务资源并分别核对会话、标签页与新增保存分组；用户旧资源不动 |

平台正常路径必须由现有入口完成，不靠临时手填、直接修改状态或逐按钮打补丁冒充自动流程。保留首次失败；有针对性的修正后重新跑受影响路径。只有处理成功并实际回读，才能关闭对应问题。

当前按用户后续授权扩充采集来源，并完整验证筛选、新稿、两平台存草稿与回读、连续调度及中断恢复。实际范围为 15 个已接入渠道及当前有效线索，旧小批样本只作历史。业务调用按实际调用记录与 token 汇总，未知记未知，不编人民币费用。

收尾顺序固定为：逐项核对通过证据 → 保存任务、稿件及验收记录 → 核对后台任务并释放本任务会话 → 交付。遇到人工控制或其他外部阻塞，明确记录未完成项，不能把“保存交接”算作通过。浏览器保存分组遵照最新用户指令，不逐组排查清理。本轮不包含关机。

## 2026-11-01 本轮恢复补充

前两筛合并调用成功后，先保存完整结果再校验逐条依据。恢复必须匹配完整提示词和 schema；一条初筛引文错误只修正该事件。存在已复用候选时，仅补未完成的初筛，合并所有候选后做一次统一二筛，不先筛新候选再重复筛全量。

定时执行保留每次尝试的状态、错误与时间。手动停止不被定时器自动继续；确定的校验错误等待处理，临时失败最多自动继续两次，并至少退避 60 秒、逐次延长。恢复沿用原 run_id；旧错误留在 timeline，不因再次开始而消失。

中新网图片限定在实际正文 `.left_zw` 中，旁边的客户端下载二维码不算正文图。相关图片搜索保留完整主题，不退化为单个泛词；没有合适图可保留无图稿。移除封面通过带版本的稿件 PATCH（`cover_url: null`）；不能通过此接口任意改成外部地址。正文中的图另由正文编辑移除。

配置目标账号的筛选在冻结输入前排除所有目标账号均已占用的同版本线索；无目标账号的手动选题仍保留。任一账号未用或线索版本变化均可继续参与；跨来源同事件的语义查重仍在创建作品前完成。

平台固定步骤先确认同一会话内所属标签并激活。滚动返回结果未知时，核对唯一目标实际位置与命中状态后再继续，不能据此重放上传或保存。公众号标题和正文写入分别依赖对应编辑框；页面其他区域变化不作为正文已改变的依据。写入结果未知必须先核对已有正文和原操作证据，在原编辑页或既有远端草稿续作。
